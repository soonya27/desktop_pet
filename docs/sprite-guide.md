# 캐릭터 이미지 에셋 가이드

> 현재 캐릭터는 이미지 없이 코드(인라인 SVG + CSS 애니메이션)로 그려져 있다.
> 이 문서는 그림 파일로 교체할 때 **어떤 파일이 어떤 규격으로 필요한지** 정리한다. 작성 2026-10-08.

## 1. 교체 구조

- 앱은 `Skin` 인터페이스([skin.ts](../src/renderer/character/skin.ts))로 그리기를 분리해 두었다. 지금은 `PlaceholderSkin`(코드 그림)이고, 이미지용 `SpriteSkin`을 추가해 바꿔 끼운다(로드맵 4차).
- 캐릭터 **이동·회전·반전은 앱이 처리**한다. 그림은 "제자리에서 오른쪽을 보고 있는 모습"만 그리면 된다.
  - 왼쪽을 볼 때는 앱이 좌우 반전한다 → 좌우 비대칭 디자인(머리카락 방향 등)은 반전 시 뒤집혀 보인다는 점만 감안.
  - 벽·천장에서는 앱이 통째로 회전한다 → 벽용 그림은 필요 없다.
- 밥그릇·하트는 캐릭터와 별개 요소다(선택 사항, 6절).

## 2. 파일 규격

| 항목 | 규격 |
|---|---|
| 형식 | PNG, 배경 투명 |
| 프레임 크기 | **160 × 240 px** (화면에는 80 × 120으로 표시, Retina 대응 2배). 세로 여유는 머리 위 요소(프로펠러, zzz)용 |
| 캐릭터 크기 | 프레임 안에서 가로 최대 150px, 세로 최대 140px 정도. 모든 프레임에서 **같은 크기** |
| 기준점 | **발바닥이 프레임 맨 아래 가운데**(x=80, y=156 근처)에 오도록. 모든 프레임 동일 — 이 점이 어긋나면 걸을 때 떨리고 벽에서 떠 보인다 |
| 배치 | 애니메이션 하나당 PNG 1장, 프레임을 **가로로 나열**(스트립). 예: 6프레임 → 960 × 160 |
| 색상 | sRGB. 외곽선·그림자는 자유 |
| 파일명 | 소문자 kebab-case, 아래 표의 이름 그대로 |

캐릭터를 더 크게 쓰고 싶으면 프레임을 200 × 200(표시 100 × 100)처럼 키워도 된다. 비율만 정사각형으로 유지하고 `skin.json`에 크기를 적는다.

## 3. 필요한 애니메이션 목록

앱의 상태(`AnimState`)와 1:1로 대응한다. **필수**는 2개뿐이고, 나머지는 없으면 대체 규칙(5절)으로 동작하므로 조금씩 추가해도 된다.

| 파일명 | 상태 | 프레임 | fps | 반복 | 내용 | 우선순위 |
|---|---|---|---|---|---|---|
| `idle.png` | 가만히 있음 | 4 | 4 | 반복 | 숨쉬기, 가끔 눈 깜빡임 | **필수** |
| `walk.png` | 걷기 | 6 | 10 | 반복 | 오른쪽으로 걷기. 발이 바닥에 붙어 있을 것 | **필수** |
| `rest.png` | 구석에서 잠자기 (1~3분) | 24 | 2 | 반복 | 누워서 뒹굴며 자는 모습. `raw/sleep.png` 5×5 시트(어두운 체커)에서 깨진 24번 프레임을 빼고 사용 (2026-10-08) | 높음 |
| `talk.png` | 알림 말풍선 중 | 4 | 6 | 반복 | 사용자 쪽을 보며 살짝 흔들기 | 높음 |

- 프레임 수·fps는 권장값이다. 다르게 그려도 `skin.json`에 적으면 된다.
- "1회" 애니메이션은 마지막 프레임에서 멈추고 앱이 다음 상태로 넘긴다.
- 총 프레임 약 70장. 최소 세트(idle + walk)는 10장.

## 4. 매니페스트 `skin.json`

이미지와 함께 두는 설명 파일. 앱은 이 파일을 읽어 어떤 PNG가 몇 프레임인지 안다.

```json
{
  "name": "chii",
  "frameWidth": 160,
  "frameHeight": 160,
  "displaySize": 80,
  "animations": {
    "idle":            { "file": "idle.png",            "frames": 4, "fps": 4,  "loop": true },
    "walk":            { "file": "walk.png",            "frames": 6, "fps": 10, "loop": true },
    "rest":            { "file": "rest.png",            "frames": 4, "fps": 3,  "loop": true },
    "talk":            { "file": "talk.png",            "frames": 4, "fps": 6,  "loop": true },
    "held":            { "file": "held.png",            "frames": 4, "fps": 6,  "loop": true },
    "fall":            { "file": "fall.png",            "frames": 2, "fps": 8,  "loop": true },
    "land":            { "file": "land.png",            "frames": 4, "fps": 12, "loop": false },
    "react-happy":     { "file": "react-happy.png",     "frames": 8, "fps": 10, "loop": false },
    "react-surprised": { "file": "react-surprised.png", "frames": 8, "fps": 10, "loop": false },
    "react-dizzy":     { "file": "react-dizzy.png",     "frames": 8, "fps": 10, "loop": false },
    "pet":             { "file": "pet.png",             "frames": 4, "fps": 5,  "loop": true },
    "eat":             { "file": "eat.png",             "frames": 6, "fps": 8,  "loop": true },
    "idle-hungry":     { "file": "idle-hungry.png",     "frames": 4, "fps": 4,  "loop": true }
  }
}
```

폴더 위치: `src/renderer/assets/skins/chii/` 에 `skin.json`과 PNG들을 함께 둔다. 앱은 이 폴더의 `*.png`만 번들하므로 원본·참고 이미지는 `raw/` 하위 폴더에 둔다.

**현재 적용된 에셋 (2026-10-08)**: Gemini가 만든 "스프라이트 시트 목업" 8장(`raw/`)에서 `scripts/extract-sprites.py`로 추출했다. 목업은 체커보드가 그림으로 칠해져 있고 라벨·테두리가 섞여 있어, 스크립트가 행 좌표를 표로 들고 프레임을 균등 분할 → 배경 제거 → 몸통(가장 큰 연결 덩어리) 높이 140px로 통일 → 발을 아래 가운데 정렬한다. 배경 제거는 색이 아니라 **외곽선**을 기준으로 한다: 가장자리에서 어두운 잉크 선을 넘지 않고 도달하는 영역을 바깥으로 보고(1px 팽창으로 대각선 틈 차단, 머리 손실 시 2px로 재처리), 발 사이처럼 바닥선에 갇힌 체커 영역은 따로 판별해 지운다. 체커보드 색이 몸통 색과 같은 시트에서도 동작한다. 프레임은 **160 × 240**(표시 80 × 120)으로, held의 프로펠러처럼 머리 위 요소가 잘리지 않게 세로를 키웠다. held는 사용자가 교체한 흰 배경 7프레임 시트(`raw/held-v2.png`)에서 뽑았고, 프로펠러·집게가 몸에 붙어 있어 전체 높이를 프레임에 맞추되 몸은 idle과 비슷한 크기가 되도록 `BODY_FIT`으로 조정했다. AI 생성 특성상 프레임 간 선 굵기·색이 조금씩 다르고 walk 프레임은 움직임이 작다. 첫 시트의 idle 행은 몸 밑면이 바닥선에 잘려 있어 쓰지 않고, react 시트의 서 있는 프레임(react-happy 1·7, react-surprised 7, react-dizzy 7)을 모아 idle로 쓴다(`COMPOSE`). 바닥선에 발만 걸린 walk·talk·rest는 발을 둥글게 이어 그린다(`FEET_EXTEND`).

새 시트를 추가할 때: 가능하면 **단색 배경(예: 순녹색 #00ff00)에 프레임 하나씩** 생성해 달라고 요청하면 추출이 훨씬 정확하다. 체커보드 목업이면 `scripts/extract-sprites.py`의 `GEOMETRY` 표에 좌표를 추가한다.

## 5. 없는 애니메이션의 대체 규칙

앱이 아래 순서로 대신 쓴다. 그래서 idle과 walk만 있어도 전부 동작한다.

| 없으면 | 대신 |
|---|---|
| `rest`, `talk`, `pet`, `eat`, `held`, `fall`, `land` | `idle` |
| `react-*` 셋 중 일부 | 있는 `react-*` 중 하나, 모두 없으면 `idle` |
| `*-hungry` | 같은 이름의 일반 버전 |

## 6. 선택 에셋

| 파일 | 규격 | 용도 | 없으면 |
|---|---|---|---|
| `bowl.png` | 80 × 48 px (표시 40 × 24), 아래 가운데가 바닥 기준점. 2~3프레임 스트립이면 음식이 줄어드는 모습 | 밥주기 때 발 앞에 놓이는 그릇 | 현재의 코드 그림 그릇 사용 |
| `heart.png` | 20 × 20 px (표시 10 × 10) | 쓰다듬기 하트 | 현재의 CSS 하트 사용 |
| `tray-template.png` + `@2x` | 16 × 16 / 32 × 32, **검정 + 투명만** | 메뉴바 아이콘 (macOS 템플릿 이미지) | 현재 아이콘 유지 |
| `icon.png` | 1024 × 1024 | 앱 아이콘 (DMG, 알림센터에 표시) | 기본 Electron 아이콘 |

## 7. 그릴 때 확인 목록

- [ ] 모든 프레임에서 발바닥 위치가 같다 (반투명하게 겹쳐 놓고 확인)
- [ ] 캐릭터가 오른쪽을 본다
- [ ] 프레임 가장자리에 그림이 잘리지 않는다 (회전·반전 시 그대로 보임)
- [ ] 걷기 프레임은 첫 프레임과 마지막 프레임이 자연스럽게 이어진다
- [ ] 1회 재생 애니메이션의 마지막 프레임은 다음 상태(idle)의 첫 프레임과 비슷한 자세다
- [ ] 치이카와 등 기존 캐릭터를 쓴다면 **개인 사용은 무방하나 배포(DMG 공개)는 저작권 문제**가 있으니 공개 전 자작 캐릭터로 교체

## 8. 전달 방법

PNG들과 `skin.json`을 한 폴더로 묶어 전달하면 된다. 받은 뒤 할 일은 `SpriteSkin` 구현(약 80줄: 스트립을 `background-image`로 두고 `background-position`을 프레임 단위로 넘기는 타이머)과 설정에서 스킨 선택 항목 추가다.
